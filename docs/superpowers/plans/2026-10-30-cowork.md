# Co-work Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver isolated, live-testable spreadsheet and document co-editing with shared native history and constrained model intentions.

**Architecture:** Lazy standalone editor bundle hosted inside the existing authenticated WebUI. Univer owns spreadsheet state/history; an OSS document adapter owns document state/history. Browser controller binds pending requests to document identity, serializes targeted transactions, and cancels on stop/switch. Server owns profile-scoped versioned snapshots and configured-provider intent inference, not editing history.

**Tech Stack:** Existing Python HTTP routing, isolated npm/Vite editor bundle, Univer OSS, document adapter selected by capability spike, pytest and browser tests.

**Spec:** docs/superpowers/specs/2026-10-30-cowork-design.md (user approval supplied explicitly in implementation request).

## Global Constraints
- Spreadsheets and documents required; PDF deferred.
- OSS only; pin dependencies and verify licenses/capabilities.
- One native history per document; latest applied targeted mutation wins.
- No arbitrary executable operations or unrestricted filesystem paths.
- Preserve auth/CSRF/profile boundaries; no new inference destination.
- No production state, consumers, restart, deploy, merge, or push.
- Synthetic fixtures and independent loopback test instance only.

## Review Focus
- Duplicate or late final transcripts must not mutate a switched document.
- Human changes during model latency must survive outside explicitly targeted regions.
- Another writable tab must not silently diverge history.
- Unsupported Office features must be rejected or visibly disclosed, never marketed as lossless.
- Profile/path confusion and stale autosave must not overwrite another document.
